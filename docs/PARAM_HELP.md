# 参数解读（Param Help）

界面上每一个参数都能解释自己：鼠标停在**参数标签**上，弹出浮层讲清「这是什么 / 各个值什么意思 / 什么时候选它」。

- **文案的唯一来源是代码**：`frontend/src/params/help.ts`。这份文档只写规范、边界和维护方式，不复制文案——两处都写必然漂移。
- **交互与视觉**：`docs/DESIGN.md` §3.8。
- **参数本身的定义**：`docs/PRD.md`，落到 `frontend/src/params/schema.ts`。

## 1. 结构

```ts
interface ParamHelp {
  summary: string;                          // 一句话：它改变画面里的什么
  options?: Record<string, string>;         // option value → 这个值长什么样、什么时候选
  tip?: string;                             // 一条提示：默认值、常见坑、和谁一起调
}
```

`PARAM_HELP` 的键是 schema 的参数 `id`，`EFFECT_HELP` 的键是 `EffectDef.id`。

浮层内容由 `helpForParam(def)` / `helpForOption(id, value)` / `helpForEffect(id)` 组装（`frontend/src/ui/state/helpStore.ts`），标签本身由 `HelpLabel` 渲染成热区。

## 2. 写作规范

三段式，缺哪段省哪段，不硬凑：

1. **一句话**（必有，≤40 字）：它改变画面里的什么。用眼睛看得见的词——颗粒更粗、边缘更硬、暗部更脏——不写「用于设置降采样倍率」这种同义反复。
2. **值解读**（枚举才有，每条 ≤25 字）：这个值长什么样 + 什么时候选它。
3. **提示**（可选，一条，≤30 字）：默认值、常见坑、要和谁一起调。

其他约定：

- 不讲数学。可以说「高质量重采样」，不要说「加窗 sinc 卷积」。
- 数值型参数在一句话里带上范围和默认值，用户不用再猜滑块两端是什么。
- 一个参数只解释自己，不解释整条流水线。需要交代上下游时用「和 XX 一起调」一句带过。
- 术语第一次出现给中文 + 英文（如「误差扩散 error diffusion」），之后只用中文。
- 文案可以随标签改，`id` 不能改：它是 schema 主键，也是这套解读的锚点。
- 选项超过 `INLINE_OPTIONS_MAX`（8）个的下拉（算法、调色板、Bayer 矩阵…），属性浮层只讲整体怎么挑，逐个值的解读挂在下拉展开后的选项行上。这条由代码自动分流，写文案时照写 `options` 即可。

## 3. 覆盖范围

| 范围 | 状态 |
|---|---|
| `PARAM_SCHEMA` 全部参数（126 条，含 Halftone 的 19 条） | 全覆盖，CI 断言不许有漏 |
| 枚举参数的每一个选项 | 全覆盖，多写少写都会让测试失败 |
| 9 种特效本身 | 全覆盖（特效卡片标题、「添加」下拉的选项行） |
| 特效实例的子参数（线间距、种子…） | 不写。标签具体、带单位，浮层只在 `EffectParamDef.hint` 存在时退回显示 |
| 预设卡片 | 不写。卡片自带一行说明，比浮层更直接 |

没写解读的参数会退回 schema 自带的 `hint`；两者都没有就不弹浮层，标签也不显示 `cursor: help`。

## 4. 一致性检查（进 CI）

`tests/engine/help.test.ts` 守着这几条，改文案或改 schema 只要对不上就红：

- 每个参数、每个特效都有解读。
- 选项解读和 schema 的选项一一对应，多写（写了不存在的值）和少写（漏了某个值）都算错。
- 一句话 ≤60 字、单值 ≤40 字（比写作规范松一档，留给个别确实需要展开的条目）。
- 选项 ≤8 的枚举把值列进属性浮层，>8 的交给选项行，并在浮层里留一句指路。
- 没有解读的参数退回 `hint`，两者都没有时返回 `null`（不弹）。

## 5. 改文案的流程

1. 改 `frontend/src/params/help.ts`。
2. `npm test` —— 一致性检查会立刻告诉你漏了什么。
3. 涉及交互或样式改动，同步 `docs/DESIGN.md` §3.8。
4. 新增参数时：schema 加一条记录 + help 加一条文案，两件事一起提交，否则测试会拦下。
